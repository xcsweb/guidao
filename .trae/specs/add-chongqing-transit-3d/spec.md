# 重庆轨道交通三维实时可视化 Spec

## Why

重庆轨道交通运营里程约 592 km、约 300 座车站，且城市高差极大（主城约 168–400 m，全域约 160–2790 m）。二维线网图无法表达"立体山城 + 轨道穿行"的空间关系。本项目提供城市级 3D 可视化：真实地形高程上的完整线网、列车运行状态与第一视角跟随，同时以"只渲染当前视野"的性能策略支撑大场景，并为后续扩展到全国城市预留架构。

## What Changes

- 新建 `cq-transit-3d` 单页应用（Vite + React + TypeScript + Three.js / WebGL2）
- 新增离线数据管线：OSM 重庆省级 PBF → 线路/车站/轨道几何/水系/桥梁/走廊建筑；Terrarium DEM → 量化高程栅格；输出标准化城市数据包与 manifest
- 新增三维引擎：DEM 分块 LOD 地形、江河水系、轨道带、车站实例、建筑分块合并、列车实例
- 新增列车运行模拟（班次表 + 时钟倍率 + 停站）与可插拔实时数据 Provider（默认模拟，可配置 HTTP 数据源）
- 新增相机系统：城市总览 / 线路聚焦 / 列车跟随（车头第一视角），平滑转场与地形避让
- 新增性能体系：视锥剔除 + 距离分级、按需渲染、DPR 上限、画质档位、性能 HUD
- 新增中文 UI：线路筛选、列车列表与跟随、时间倍率、高程夸张、设置与数据来源说明
- 新增扩展机制：城市注册表 manifest 与统一数据 schema，新增城市无需改动引擎

## Impact

- Affected specs: `city-data-pipeline`（新增）、`terrain-3d-rendering`（新增）、`transit-3d-viewer`（新增）、`realtime-provider`（新增）
- Affected code: 全新项目，主要包括 `scripts/`（数据构建）、`src/engine/`（渲染引擎）、`src/sim/`（列车模拟与数据源）、`src/ui/`（界面）、`public/data/cq/`（重庆数据包）

## 非目标

- 不接入官方实时列车 API（重庆轨道暂无公开实时接口），内置为"模拟实时"，并保留接入位
- 不做厘米级建筑精模与室内场景，建筑仅做体块级还原
- 不交付全国数据；仅交付重庆数据包，但架构支持扩展

## ADDED Requirements

### Requirement: 城市数据包与数据管线

系统 SHALL 提供可重复执行的离线构建脚本，从公开数据源生成标准化城市数据包，包含 `manifest.json`、线网数据、地形高程栅格、水系/桥梁/走廊建筑要素，并输出构建校验报告。

#### Scenario: 首次构建

- **WHEN** 执行 `npm run build:data`
- **THEN** 在 `public/data/cq/` 生成 manifest、线网、地形二进制、要素数据，并打印线路数、车站数、高程范围、各资产体积

#### Scenario: 重复构建与断点续传

- **WHEN** 原始数据已缓存或下载中断
- **THEN** 脚本复用缓存/断点续传；失败时返回非零退出码且不产出半成品数据包

#### Scenario: 数据完整性校验

- **WHEN** 构建完成
- **THEN** 校验每条线路至少有 2 座车站、轨道折线连续、坐标落在重庆范围内；异常项写入报告

### Requirement: 真实地形与高程比例

系统 SHALL 基于 DEM 真实高程生成地形网格，垂直比例默认 1:1，并提供 0.5–3.0 的夸张系数调节。

#### Scenario: 高程一致性

- **WHEN** 将夸张系数设为 1.0 并定位到任一点位
- **THEN** 地形高度与该点 DEM 采样值一致（误差不超过采样精度）

#### Scenario: 高程夸张联动

- **WHEN** 拖动夸张系数
- **THEN** 地形、轨道、车站、列车同步缩放高程，轨道不脱离地表

### Requirement: 地形 LOD 与无缝拼接

系统 SHALL 将地形切分为规则块并采用四叉树 LOD，按视距调整网格密度，块间无可见裂缝。

#### Scenario: 近远景过渡

- **WHEN** 相机从高空俯冲到贴地视角
- **THEN** 近处使用最高精度块、远处降级，接缝处无空洞或 T 型裂缝

### Requirement: 全线路网渲染

系统 SHALL 渲染重庆轨道交通数据包中的全部运营线路（当前实测 OSM 可覆盖环线、1、2、3、4、5、6、国博支线、9、10、18、江跳线、璧铜线，最终以数据包实际线路为准），按线路官方配色区分，轨道几何贴合地形起伏。

#### Scenario: 线路聚焦

- **WHEN** 用户选择某条线路
- **THEN** 该线路高亮、其余线路降透明度，相机平滑飞至该线路范围

#### Scenario: 车站交互

- **WHEN** 用户点击车站
- **THEN** 展示站名、所属线路、经纬度与高程

### Requirement: 列车运行模拟与实时数据接口

系统 SHALL 提供时钟驱动的列车运行（发车班次、区间运行、停站、折返），并暴露统一的实时数据 Provider 接口。

#### Scenario: 班次运行

- **WHEN** 应用启动
- **THEN** 各线路按班次表生成列车，位置随时间平滑推进，停站时速度归零并显示到站倒计时

#### Scenario: 时间控制

- **WHEN** 切换暂停 / 1x / 10x / 60x
- **THEN** 列车位置、到站信息同步变化，切换过程无跳变

#### Scenario: 接入外部实时源

- **WHEN** 配置了 `VITE_REALTIME_URL`
- **THEN** 使用 HTTP Provider 拉取列车位置；请求失败自动回退模拟数据，UI 明确标注当前数据来源与更新时刻

### Requirement: 列车跟随视角

系统 SHALL 提供列车跟随模式，相机位于车头位置并朝向前进方向，随轨道坡度俯仰，且不得穿入地形或建筑。

#### Scenario: 进入与退出跟随

- **WHEN** 用户跟随某列车
- **THEN** 相机平滑过渡至车头视角，HUD 显示车次、线路、速度、下一站与距离；退出后回到跟随前的总览视角

#### Scenario: 沿线风景

- **WHEN** 列车行驶于江边、桥梁、隧道与高架区间
- **THEN** 视角稳定，可见真实地形高差、江面与桥体，不出现穿模与剧烈抖动

### Requirement: 性能与"只渲染当前视野"

系统 SHALL 仅渲染相机视锥内且满足距离阈值的对象，静态对象使用实例化或分块合并。

#### Scenario: 性能面板

- **WHEN** 打开性能 HUD
- **THEN** 显示 FPS、draw calls、三角形数、可见地形块数；中画质 1080p 目标 ≥ 45 FPS

#### Scenario: 页面不可见

- **WHEN** 标签页隐藏或窗口最小化
- **THEN** 暂停渲染与模拟推进，恢复后从正确时刻继续

#### Scenario: 视锥剔除生效

- **WHEN** 相机朝向某一城区
- **THEN** 视野外地形块、建筑分块与列车不参与绘制（draw calls 随视野变化）

### Requirement: 画质档位与自适应降级

系统 SHALL 提供低/中/高画质档位，控制 DPR、地形精度、建筑与标签密度，并在持续低帧率时自动降级。

#### Scenario: 手动切换画质

- **WHEN** 用户切换画质档位
- **THEN** DPR、地形块细分、建筑显示与标签密度立即生效，且不导致相机跳变

#### Scenario: 自动降级

- **WHEN** 帧率连续低于阈值超过设定时长
- **THEN** 自动降低 DPR/隐藏远景建筑细节，并在 HUD 提示

### Requirement: 城市扩展（全国）

系统 SHALL 通过城市注册表与统一数据 schema 加载城市数据，渲染引擎不得硬编码重庆专属逻辑。

#### Scenario: 扩展新城市

- **WHEN** 在注册表中新增一个符合 schema 的城市数据包
- **THEN** 应用可切换加载该城市（当前交付仅内置重庆），无需修改渲染核心

#### Scenario: 数据缺失降级

- **WHEN** 某城市缺少建筑或水系数据
- **THEN** 引擎跳过对应图层并正常运行，控制台给出提示

### Requirement: 中文界面与基础可用性

系统 SHALL 提供中文界面、加载进度、错误提示、键盘快捷键与基础响应式布局。

#### Scenario: 加载反馈

- **WHEN** 数据包加载中
- **THEN** 显示分阶段进度（地形/线网/要素）与可读的失败原因

#### Scenario: 快捷键

- **WHEN** 按下空格 / F / L / Esc
- **THEN** 分别暂停或继续、跟随当前列车、切换线路面板、退出跟随或关闭弹层

## 数据与合规

- 线网与建筑/水系数据来源 OpenStreetMap（ODbL），应用内保留署名与许可链接
- 地形高程来源 Terrarium / AWS Open Data（SRTM 等），应用内标注
- 列车位置为模拟数据，界面明确显示"模拟实时"，接入真实源后显示来源与延迟
